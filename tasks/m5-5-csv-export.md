# M5.5 — CSV export from the result grid

## Goal

**Before (post-M5.4):** The result grid in each tab renders rows in a real
`<table>` with sort/resize/preview. The user has no way to get the data out
— no Copy, no Download, no CSV. Every result is locked inside the webview.

**After:** Right-click on the result grid → context menu with "Export CSV…"
(and "Copy as CSV"). Choosing "Export CSV…" opens the OS file-save dialog
(via `@tauri-apps/plugin-dialog`), defaults the filename to
`<server>-<database>-YYYYMMDD-HHMMSS[.partial].csv`, and writes the
RFC 4180-encoded buffer to disk. "Copy as CSV" puts the same payload on
the clipboard.

The export covers exactly the **materialized** buffer — whatever rows are
in `tab.active.rows` at click time. If `tab.active.hasMore` is true (cursor
still open), the filename includes `.partial` and the export's first line
is a documented one-line note (`# Partial export: N rows, cursor still open. -- generated by Quill`)
**as a leading SQL-style comment** that human-readable CSV consumers will
ignore as a stray line. Tools that ingest CSV strictly will choke; the
filename `.partial` is the canonical signal. (See "Design choices" — there's
no portable in-band way to mark a partial CSV.)

The grid's sort is **honoured** on export — the file mirrors what the user
sees, not insertion order. Column widths and the cell preview state are not
relevant. Errors (no active result, dialog cancelled, write failure) surface
as the tab's `lastError`.

This task adds **one Tauri plugin** (`tauri-plugin-dialog` + its JS
counterpart `@tauri-apps/plugin-dialog`), one tiny Rust permission entry,
and edits `ResultGrid.svelte` + `+page.svelte`. No backend command surface
changes.

## Current state

### `src/lib/ResultGrid.svelte` — the file this task extends

Read it in full before starting. Today it accepts:

```ts
{ columns, rows, statusLine, hasMore, loadingMore, onLoadMore, canLoadMore }
```

Owns its own sort state (`sortCol`, `sortDir`, `sortedRows: $derived`),
column widths, and a cell-preview `<dialog>`. M5.5 adds a context-menu
overlay and surfaces the *sorted* row buffer to the parent for export.

The parent (`+page.svelte`) holds the materialized rows on the tab. The
**sorted view** lives inside `ResultGrid`. To export the sorted view, the
grid must either:

- Compute and pass the sorted buffer up to the parent on demand, or
- Own the export action itself.

Pick the latter: the grid emits a request via `onExportCsv` /
`onCopyCsv` callbacks that take *no* arguments — the grid computes the
final array of rows internally and the parent supplies metadata
(filename, columns are already on the props). This keeps the sort
contained.

### `src/lib/tabs.ts` — unchanged

No new tab state needed.

### `src/routes/+page.svelte` — wires the new callbacks

Adds two small handler functions that build the filename and call into
the dialog plugin / clipboard.

### Tauri plugin install

The dialog plugin must be installed on **both** sides:

- Rust: `tauri-plugin-dialog` in `Cargo.toml`, `.plugin(tauri_plugin_dialog::init())`
  in `lib.rs`.
- JS: `@tauri-apps/plugin-dialog` in `package.json` deps.

Tauri 2's capability/permission model requires an explicit allowlist in
`src-tauri/capabilities/default.json`. The default capability file ships
with `core:default`, opener:default, etc. M5.5 adds `dialog:default`.

The clipboard side uses the **webview's standard `navigator.clipboard.writeText`** —
no separate plugin needed. (Tauri 2 lets the webview's clipboard API
work out of the box for text content in the user-action context.)

## Design choices baked into this spec

- **RFC 4180 encoding in TS, not Rust.** The row buffer lives in the
  frontend; piping it through a Tauri command for encoding would double
  the memory and add latency for no benefit. The encoder is ~30 lines.
- **Headers row is always included.** Column names per `columns[i].name`,
  un-quoted unless they need it. Most apps consuming the CSV expect a
  header; opt-out is a CLI thing, not a personal-app thing.
- **`.partial` filename marker for streamed results.** There's no in-band
  way to flag a partial CSV that both spreadsheet apps and `csv`-parsing
  scripts respect. The filename is the canonical signal; we additionally
  prepend a single comment line (`# Partial export: ...`) that humans
  will read in a text editor. Spreadsheets will import the line as a
  one-cell row with a `#` cell — annoying but visible. Document the
  trade-off.
  
  Alternative: write a sidecar `.txt` file. Rejected — two files for one
  action is worse UX than the imperfect inline note.
- **Sorted view, not insertion order.** The CSV mirrors what the user
  is looking at. If they sort by `created_at desc` and export, the file
  is sorted by `created_at desc`. M3.6's `sortedRows` derived value is
  exactly what we need; no extra work.
- **Cell stringification matches the grid's `stringify` helper.** Long
  values are **not** truncated in the CSV (only in the grid preview);
  JSON is serialised compactly (no indentation) because spreadsheet apps
  hate multi-line cells.
- **Null is the empty string `""` in CSV.** Some tools want the literal
  `NULL`, but the empty cell is the spreadsheet convention. The grid's
  null marker (the muted-italic "NULL" string) is presentation; the file
  is bytes.
- **No BOM.** UTF-8 without BOM. Tauri webviews are UTF-8; spreadsheet
  apps on macOS / Linux read this fine. Excel-on-Windows can mis-detect
  encoding — a Windows tester would want a BOM, but Quill is personal-
  use on Linux for now (see `CLAUDE.md`). Easy to flip later.
- **Newline = `\r\n`.** RFC 4180 mandates CRLF. Modern tools accept LF
  too, but the standard is the standard; cost is one byte per row.
- **Dialog default folder = home.** No "remember last folder" in M5;
  Tauri's `defaultPath: undefined` lets the OS pick. M6 polish can
  remember.
- **Copy-as-CSV puts the same payload on the clipboard.** Use
  `navigator.clipboard.writeText`. If clipboard write fails (rare,
  permission-denied in some webview contexts), surface the error.
- **Context menu suppresses the webview default.** `oncontextmenu`
  intercepts and `preventDefault`s; the browser's "Inspect Element" menu
  doesn't appear over the grid. (Tauri 2 also suppresses it globally by
  default — verify in smoke; if it shows, add the global suppression at
  the `+page.svelte` level.)
- **Export disabled while `loadingMore` is true** — exporting mid-fetch
  is fine in principle but the resulting `.partial` may not match what
  the user thinks they're getting. Disable for ~100ms; it's not a real
  user pain point.
- **No "Export all" option.** Quill won't drain the cursor in the
  background to fetch everything. Per principle 1, that would be hidden
  work. If the user wants the whole result, they Load more to the end,
  then Export.

### 5. `src/lib/csv.ts` — new module: RFC 4180 encoder

```ts
//! RFC 4180 CSV encoding for the result grid's export and clipboard
//! flows.
//!
//! - Header row from column names (always emitted).
//! - Field quoting when the field contains `,`, `"`, `\r`, or `\n`.
//! - Interior `"` doubled to `""`.
//! - Lines separated by `\r\n` per RFC 4180.
//! - Null and undefined render as empty cells.
//! - Non-string values stringify via `String(...)`; objects via
//!   `JSON.stringify(...)` (compact, no indent).

import type { ColumnMeta } from "./tauri";

const QUOTE_RE = /[,"\r\n]/;

function field(value: unknown): string {
  if (value === null || value === undefined) return "";
  let s: string;
  if (typeof value === "string") s = value;
  else if (typeof value === "object") {
    try {
      s = JSON.stringify(value);
    } catch {
      s = String(value);
    }
  } else {
    s = String(value);
  }
  if (QUOTE_RE.test(s)) {
    return `"${s.replace(/"/g, '""')}"`;
  }
  return s;
}

/** Encode a result set as RFC 4180 CSV.  `prelude` (if provided) is
 *  prepended verbatim followed by `\r\n` — used for the `.partial`
 *  comment line.  Most consumers will treat that line as a stray row;
 *  the filename `.partial` suffix is the canonical signal. */
export function encodeCsv(
  columns: ColumnMeta[],
  rows: unknown[][],
  prelude?: string,
): string {
  const out: string[] = [];
  if (prelude) out.push(prelude);
  out.push(columns.map((c) => field(c.name)).join(","));
  for (const row of rows) {
    out.push(row.map(field).join(","));
  }
  return out.join("\r\n") + "\r\n";
}
```

### 7. `src/routes/+page.svelte` — wire export handlers

**Import the CSV helper and dialog plugin:**

```ts
import { encodeCsv } from "$lib/csv";
import { save } from "@tauri-apps/plugin-dialog";
import { writeTextFile } from "@tauri-apps/plugin-fs"; // see note below
```

> **Note on `plugin-fs`:** Tauri 2's `dialog.save` only returns a path;
> writing the file requires either `@tauri-apps/plugin-fs` or invoking
> via Tauri's core. The smallest path is to add `plugin-fs` *and*
> grant `fs:default` (or scoped `fs:allow-write-file`) in the
> capability. **Alternative**: write the file from Rust via a custom
> `write_csv(path, content)` command, dodging `plugin-fs`. Decide
> below.

**Decision:** ship a small custom Tauri command `write_csv(path,
content)` instead of pulling in `plugin-fs`. Reasons:

1. `plugin-fs` requires a *scope* (allowlist of writable paths). Without
   it, every write needs an explicit user gesture and a stable allowlist
   — but the OS save dialog already provides the gesture and the user-
   picked path. Replicating that in `plugin-fs` permissions is fiddly.
2. The custom command is ~10 lines of Rust and zero JS plumbing beyond
   the existing `invoke`.
3. No new plugin = no extra permission entry beyond `dialog:default`.

**Add to `src-tauri/src/commands/mod.rs`** (M5.5's only backend change):

```rust
/// Write a UTF-8 string to `path`.  Called from the CSV export flow
/// after the user picks a destination via the OS save dialog.  The
/// path is user-supplied; we don't validate it (the dialog already did).
#[tauri::command]
pub async fn write_text_file(path: String, content: String) -> Result<(), CommandError> {
    tokio::fs::write(&path, content)
        .await
        .map_err(|e| CommandError::Store(format!("write {path}: {e}")))?;
    Ok(())
}
```

Register in `lib.rs`:

```rust
commands::write_text_file,
```

TS binding in `src/lib/tauri.ts`:

```ts
writeTextFile: (path: string, content: string) =>
  invoke<void>("write_text_file", { path, content }),
```

**Now wire the export handlers in `+page.svelte`:**

```ts
import { save } from "@tauri-apps/plugin-dialog";
import { encodeCsv } from "$lib/csv";

function csvFilename(tab: Tab): string {
  const server = connections.find((c) => c.id === tab.serverId)?.name ?? "server";
  const safe = (s: string) => s.replace(/[^a-zA-Z0-9._-]+/g, "_");
  const now = new Date();
  const stamp =
    `${now.getFullYear()}${pad(now.getMonth() + 1)}${pad(now.getDate())}` +
    `-${pad(now.getHours())}${pad(now.getMinutes())}${pad(now.getSeconds())}`;
  const partial = tab.active?.hasMore ? ".partial" : "";
  return `${safe(server)}-${safe(tab.database)}-${stamp}${partial}.csv`;
}
function pad(n: number): string {
  return n < 10 ? `0${n}` : `${n}`;
}

async function exportCsv(tab: Tab, sortedRows: unknown[][]) {
  if (!tab.active) return;
  const filename = csvFilename(tab);
  let target: string | null;
  try {
    target = await save({
      defaultPath: filename,
      filters: [{ name: "CSV", extensions: ["csv"] }],
    });
  } catch (err) {
    tab.lastError = err as CommandError;
    return;
  }
  if (!target) return; // user cancelled

  const prelude =
    tab.active.hasMore
      ? `# Partial export: ${tab.active.rowCount} rows, cursor still open. -- generated by Quill`
      : undefined;
  const payload = encodeCsv(tab.active.columns, sortedRows, prelude);

  try {
    await api.writeTextFile(target, payload);
  } catch (err) {
    tab.lastError = err as CommandError;
  }
}

async function copyCsv(tab: Tab, sortedRows: unknown[][]) {
  if (!tab.active) return;
  const prelude = tab.active.hasMore
    ? `# Partial export: ${tab.active.rowCount} rows, cursor still open. -- generated by Quill`
    : undefined;
  const payload = encodeCsv(tab.active.columns, sortedRows, prelude);
  try {
    await navigator.clipboard.writeText(payload);
  } catch (err) {
    tab.lastError = {
      kind: "Pg",
      message: `clipboard write failed: ${err}`,
    };
  }
}
```

**Wire the props into `<ResultGrid>`:**

## Known gotchas

- **Capability permission name.** Tauri 2's permission strings are
  `<plugin>:<group>` (e.g. `dialog:default`). Missing the entry produces
  a runtime error like "permission denied: dialog.save". The error
  surfaces in devtools as a Tauri IPC rejection; if the smoke test
  shows it, double-check `capabilities/default.json`.
- **Re-running `pnpm approve-builds`.** `@tauri-apps/plugin-dialog`'s
  native bindings may need approval per `CLAUDE.md` § Tooling. If the
  install warns about a build script, run `pnpm approve-builds
  @tauri-apps/plugin-dialog` and re-install. The approval lands in
  `pnpm-workspace.yaml`.
- **`save()` returns `null` on user cancel**, not a thrown error. The
  handler must early-return without raising.
- **`navigator.clipboard.writeText` requires a user gesture context.**
  The context-menu click counts as a gesture; the webview accepts it.
  If you call `copyCsv` from a non-user code path (e.g. a `$effect`),
  the browser blocks. Don't auto-copy on result open.
- **Sorted vs unsorted parity.** `sortedRows` inside `<ResultGrid>` is
  the source of truth. The parent must not assume `tab.active.rows ===
  sortedRows`; that's why the handler signature passes the array
  explicitly. If you accidentally pass `tab.active.rows`, the file
  silently mirrors insertion order — a stealth bug.
- **CSV cell types vs preview types.** The grid's `stringify` collapses
  null to `"NULL"` for display; the CSV encoder writes `""` for null.
  Keep these definitions distinct — sharing the helper would force the
  CSV to write the literal word NULL, which most spreadsheets parse as
  the string `"NULL"`, not an empty cell. The duplication is correct.
- **JSON cells.** Objects (JSONB columns) serialise to compact JSON
  `{"foo":1}` — single line, no indent. Excel and Numbers handle this
  fine; the cell appears verbatim. Pretty-printed JSON inside a CSV
  cell breaks naive parsers.
- **Newlines in cell values.** A `TEXT` cell containing `\n` is quoted
  and the newline is preserved inside the quotes per RFC 4180. Most
  spreadsheet apps render it as a multi-line cell; CLI `csv` tools
  (Python's `csv` module, ripgrep) handle it correctly.
- **CRLF line separator.** `encodeCsv` joins with `"\r\n"`. Unix tools
  reading the file see literal `\r\n` line endings — `cat`, `head`, etc.
  show stray `^M` only if forced (`cat -A`). `wc -l` counts correctly.
- **No BOM.** Tested on Linux + macOS; Windows Excel users may see
  mojibake on non-ASCII characters. Easy fix later: prepend `﻿`
  to the payload behind a settings flag.
- **`@tauri-apps/plugin-dialog` is dual-licensed Apache/MIT** — the
  repo's `MIT` license is compatible. No license-tracking work needed.
- **`tokio::fs::write`** truncates the file. That matches the OS save-
  dialog's semantics (overwrite-confirm is the dialog's job, not ours).
  If the user picks an existing path, they've already confirmed.
- **The OS save dialog blocks the webview's UI thread**. Tauri runs it
  on the main app thread; the webview shows a busy cursor. That's fine
  — the user is making a choice.
- **Filename sanitisation** strips characters that some filesystems
  reject (`?`, `*`, `:` on Windows; spaces become `_` for shell-
  friendliness). The dialog overrides the filename if the user types
  something else, so this is just a sensible default.
- **`.partial` suffix vs the comment line.** Decided: keep both. The
  suffix is the canonical machine signal; the comment is the
  human-readable signal. If a stricter consumer wants pure RFC 4180,
  they can `tail -n +2` to strip the comment. Document this in the
  smoke output.
- **`onclick` window listener at the bottom of `ResultGrid.svelte`**
  conflicts with the existing `<svelte:window onclick={closeMenu}>` in
  `+page.svelte`. Both close their respective menus; they don't fight
  because each menu's open state is local. Confirm in the smoke test
  that opening one menu doesn't accidentally close the other.
- **Context-menu position near the bottom-right edge** can overflow the
  viewport. M5.5 ships without overflow handling; the menu may render
  partially off-screen. M6 polish: clamp to viewport.
- **The user might Copy then Paste into a webview-internal field.** The
  CSV string contains newlines and quotes; the paste target may
  reformat. Not our problem — same constraint applies to any clipboard
  use.

### Manual smoke test

```bash
./install.sh   # pulls in tauri-plugin-dialog + @tauri-apps/plugin-dialog
docker run -d --name quill-pg -e POSTGRES_PASSWORD=dev -p 5432:5432 postgres:17
docker exec -it quill-pg psql -U postgres -c "
  CREATE TABLE big AS SELECT generate_series(1, 5000) AS n, md5(random()::text) AS hash;
"
./run.sh
```

1. Connect, open `postgres`, run `SELECT * FROM big LIMIT 50`. Right-click on
   the grid → menu shows "Export CSV…" and "Copy as CSV".
2. Click "Export CSV…". OS save dialog opens. Default filename ends in
   `.csv` (no `.partial`) because `LIMIT 50` is fully materialised. Save
   to `/tmp/test.csv`.
3. Inspect: `head /tmp/test.csv`. First line is the header
   (`n,hash`). Lines use CRLF (`file /tmp/test.csv` reports "with CRLF
   line terminators"). Rows are in **insertion order** (no sort yet).
4. In the grid, click the `n` column header → sort descending. Right-click →
   Export CSV → save again. The new file's row order is reversed (5000
   first). Confirms the sorted view is exported.
5. Run `SELECT * FROM big`. The grid shows 1000 rows; status line reads
   `cursor open`. Right-click → Export. **Filename defaults to
   `...partial.csv`.** Save. First line of the file is the `# Partial
   export: 1000 rows, cursor still open.` comment; second line is the
   header.
6. Click "Copy as CSV" on the same partial result. Paste into any text
   editor — the prelude + header + 1000 rows are present.
7. Verify the prelude appears only when `hasMore=true`. Run a query
   that returns < 1000 rows; export — no prelude, filename no `.partial`.
8. Run `SELECT * FROM (VALUES (1, 'has "quotes" and ,commas'), (2, 'line\nbreak')) AS t(n, s)`.
   Export. Inspect: cell with quotes is rendered `"has ""quotes"" and ,commas"`;
   cell with newline is quoted and the newline is preserved.
9. Run `SELECT row_to_json(big) AS doc FROM big LIMIT 3`. Export. JSON
   cells are compact, valid JSON, on a single line in the file.
10. Cancel the save dialog (Esc / Cancel button). No file is written;
    no inline error. The grid context menu closes.
11. With no Postgres running, simulate a write error: pick a path the OS
    rejects (e.g. `/root/no.csv` as a non-root user). Inline error
    surfaces with `kind: "Store"` and the OS message.
12. Right-click → menu opens; click elsewhere on the page → menu
    closes. Right-click again — the previous menu closed cleanly (no
    stale entries).
13. Open two tabs, give each its own result. Right-click in tab A's grid
    → only tab A's data is in the export. Switch tabs, verify the same
    for B.

## Out of scope

- TSV export, JSON export, SQL `INSERT` script export — v1.1.
- "Export all" that drains the cursor — never; principle 1.
- UTF-8 BOM toggle — M6 settings.
- Remember-last-folder for the save dialog — M6 settings.
- Per-column include/exclude in export — v1.1.
- Streaming export to disk (avoid materializing the full string) — only
  relevant past 50 MB results; M3 caps the buffer well below that.
- Excel `.xlsx` export — out of scope; spreadsheet apps import CSV fine.
- Server-side `COPY TO STDOUT` for huge tables — out of scope for v1;
  this is "export what's loaded," not "stream the whole table."
- Sharing exports via cloud / URL — out of scope.
- Keyboard shortcut for Export (e.g. Cmd+S) — M6 polish.
- Showing the saved file in the OS file manager after export — M6 polish.
- Auto-quoting the entire row regardless of content (some dialects of
  CSV require it) — RFC 4180 minimal quoting is the choice.
- File-format options inside the save dialog (delimiter pick, etc.) —
  out of scope; CSV-with-commas is the only mode.
